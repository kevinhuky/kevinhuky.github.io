# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Commands

- Build the static site: `python build.py`
- Preview locally after building: `python -m http.server 8000 -d site`, then open `http://127.0.0.1:8000`
- Check the build script syntax: `python -m py_compile build.py`

There is no package manifest or configured test/lint command in this repository. The build uses only Python standard-library modules.

## Architecture

This is a minimal static blog. Markdown source content lives under `docs/`, and `build.py` renders the complete site into `site/`.

Key flow in `build.py`:

1. `read_posts()` loads Markdown posts from `docs/blog/posts/*.md`, parses front matter, skips `draft: true`, and sorts posts by date descending.
2. `render_markdown()` is a custom lightweight Markdown renderer. It supports headings, paragraphs, links, images, emphasis, code fences, blockquotes, lists, horizontal rules, and simple tables. It is not a full Markdown implementation.
3. Page renderers generate the site:
   - `render_home()` writes the home page and `/blog/` page with recent full posts.
   - `render_post()` writes individual post pages under `/blog/<slug>/`.
   - `render_archive()` writes `/archive/`.
   - `render_category()` writes year archive pages and category pages.
   - `render_rss()` and `render_sitemap()` write feed and sitemap outputs.
4. `main()` deletes and recreates `site/`, copies `src/style.css` to `site/style.css`, copies `docs/CNAME` if present, renders HTML/XML files, compresses the sitemap, and copies `docs/assets/` to `site/assets/`.

## Content model

Posts are Markdown files in `docs/blog/posts/` with front matter like:

```markdown
---
title: 文章标题
draft: false
date: 2026-01-01
slug: post-slug
categories:
  - Engineering
---
```

`<!-- more -->` marks the excerpt boundary for summaries; without it, `build.py` derives an excerpt from the first 220 plain-text characters.

Relative links to other Markdown posts are rewritten through a `link_map` built from post filenames. Category URLs use `slugify()` and support Chinese characters.

## Styling and generated files

- Edit global styles in `src/style.css`; `site/style.css` is generated by `python build.py`.
- `site/` is the generated output directory. If changing source content, styles, or generator code, rebuild before checking generated pages.
- Static assets should go under `docs/assets/`; the build copies them into `site/assets/`.

## Deployment

GitHub Pages deployment is configured in `.github/workflows/publish.yml`. On pushes to `main` or manual workflow dispatch, GitHub Actions uses Python 3.11, runs `python build.py`, uploads `site/`, and deploys it with `actions/deploy-pages`.
